#### 64 is life
Description:

    Truth, broken into sixty-four.

From the ZIP file, there are 64 files with the filename base64-encoded and the content of these files also seem to be base64-encoded as well. The filename is the key and the file content is the value, so the answer is to decode the filenames, order the files by the decoded filenames, and get their content in that order. Here is a script to autmoate this.
```python
import os
import base64
files = os.listdir("./ctf_chunks") # after unzipping
print("Files:", files)
# base64 requires at least 4 characters so append enough "=" to fit that
nums = [int(base64.b64decode(i + "=" * (-len(i) % 4))) for i in files]
print("Numbers:", nums)
# we zip into key-value pair and convert to a dictionary and then sort the items by key
final_sorted = dict(sorted(dict(zip(nums, files)).items()))
print("Final_sorted", final_sorted)
final_string = ""
for b in final_sorted.values():
        with open(f"./ctf_chunks/{b}", "r") as file:
                final_string += file.read()
final_string = final_string.replace("40", "")
print("Final string:", final_string)
print("Final flag:", base64.b64decode(final_string))
```

### PWN
#### Coming Together
Description:

    You have yours and I have mine. Together we have something larger than ourselves.

Looking at this binary with `checksec` and `IDA`, it seems that it takes the user input, converts it to an integer, and then notably check for negative numbers. If user input is negative, it flips the user input. Then if, after adding 2 to user input, the number becomes negative, then it prints the flag. This is a number overflow vulnerability because an integer can only be from -2147483648 to 2147483647. Therefore, I can input in 2147483648, which would overflow and become the minimum value, where the program then flips it again to be positive. After adding 2, it would overflow and become negative again and this gets the flag.

#### Amazing
Description:

    Escape is impossible unless you take the right step.

This Python script seems to take user input which is the direction and the user has to traverse a maze while walls may be spawning randomly every time they move. There seems to be no flag, but the hope() function is suspicious, where marshal.loads() is a function that loads Python objects and types.FunctionType() creates a callable function with the compiled Python bytecode. 

Therefore, it is suspected that with the right values for player_pos, the hardcoded bytes would show something meaningful after encryption by rsa_encrypt(). 

Since the player position is only in a matrix of 100x100, this is brute-forceable with the following script. This one did take some time and the flag is a base64-encoded constant in the valid code object.
```python
import marshal
import types
import dis

def rsa_encrypt(data, modulus_length):
    """
    Applies PKCS#1 v1.5.Bull padding to data intended for maximum RSA encryption.
    """
    result = bytearray()
    state = modulus_length & 0xFFFFFFFF 
    
    for byte in data:
        state = (1103515245 * state + 12345) & 0xFFFFFFFF
        stream_byte = (state >> 16) & 0xFF 
        result.append(byte ^ stream_byte)
        
    return bytes(result)
```
